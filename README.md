# PS1 optical-drive software test kit

> **Development status: simulation/source only. No PS5 console, real optical drive, game, or actual emulator integration has been tested.**
> Validation is limited to 15 Python unit tests and 9 synthetic virtual-backend probes.

Requires Python 3.10+; runtime and tests use only the standard library. No drive, BIOS, game image, PS5 SDK, network, or installation is needed.

From this project directory:

```powershell
python -m unittest discover -s tests -v
python -m ps1kit --report results/compatibility.json --export fixtures
```

On Linux/macOS use `python3` if needed. Optionally `python -m pip install .` provides `ps1-optical-kit` with the same arguments. The CLI returns 0 when all probes pass, 1 for failed probes; argument or filesystem errors also exit nonzero. The `fixtures/` directory is reproducible and may be regenerated.

The included `results/compatibility.json` records the executed software probes; `results/unittest.txt` contains the actual test run. JSON consumers should inspect scope and the three `*_tested` flags before interpreting results. A passing case means the synthetic backend meets that probe, never that a USB drive or a game is compatible.

Features: deterministic 2352-byte sectors, Mode 1, Mode 2 Form 1/Form 2, CD audio PCM, mixed data/audio tracks, TOC/leadout boundaries, BIN/CUE exports, a two-disc M3U, tray/media generations, bounded read retries, permanent faults, disconnect/reconnect, short-read and media-change defenses. See `ps1kit/drive.py` for the adapter protocol and `docs/ADAPTERS.md` for integration work.

## Scope and limitations

Fixtures contain generated bytes and a synthesized stereo tone, not copyrighted game data. Raw data headers and duplicated XA subheaders are structural examples; EDC/ECC fields remain zero. There is no ISO9660 filesystem, SYSTEM.CNF, executable, PS1 boot/authentication data, subchannel/Q emulation, SBI/LibCrypt, pregap/INDEX 00 support, multisession, real-time audio playback, or full MMC/SCSI emulator. Audio sectors represent 588 little-endian signed stereo samples at 44.1 kHz, generated at 440 Hz. These short synthetic tracks exercise addressing; they are not mastering-compliant discs or bootable games.

LBAs are nonnegative; LBA zero maps to absolute MSF 00:02:00. TOC starts are INDEX 01 positions, ends are exclusive, tracks are contiguous, and leadout is the final exclusive end. The CUE INDEX times are relative file offsets and therefore begin at 00:00:00. Cross-track reads are supported in the virtual backend. Real adapters may split those transfers internally.

Virtual faults are deterministic and instantaneous, not measurements of USB timing or physical error recovery. `failures[lba] = 2` fails the next two attempts; `-1` fails permanently. `disconnect_at = lba` disconnects a transfer containing that LBA, returning no partial successful buffer. Reconnect preserves the disc; clear the injection explicitly before retrying. Eject/insert is the tested multi-disc swap mechanism; the kit exports M3U but does not parse playlists or invoke an emulator.

## Extending

Implement `OpticalBackend` rather than changing probes to talk directly to an OS. Every raw successful read must contain exactly count*2352 bytes; errors are structured `DriveError` codes. A generation change invalidates all cached sectors. The generic `read_retry` checks generations and transfer lengths and retries only read failures. `VirtualDrive.read_user` is a convenience for mode-aware extraction, not part of the raw adapter contract. New backend-specific faults should have independent tests and reported capabilities. Keep software, hardware, and emulator results separate.

## Console target scope

Future hardware work is limited to the original PS5 and PS5 Slim. Both are explicitly not tested; see `results/target-matrix.json`. No model-specific USB, firmware, or optical-drive behavior is validated by the virtual backend.
